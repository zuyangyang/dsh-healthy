# dsh-healthy

把家里每个人的体检报告、生病经过、身体状态，记成**可以追溯、可以比较、能直接拿给医生看**的健康档案。

- 一句话进来："妈今天早上头晕，量了血压 138/88" → 症状 + 血压两条记录
- 整份体检报告进来：先预览识别到哪些项目、哪几项没认出来，确认后再落盘，报告原文一字不改地存下来
- 问得出来：某个指标三年怎么变的、异常持续了多久、上次建议的复查做了没有
- 拿得出去：一页就诊摘要卡（慢病、过敏、在用药物、近期异常、待复查）

数据是本地文件（NDJSON），默认每人只看自己的。接 [dsh-family-auth](https://github.com/zuyangyang/dsh-family-auth) 后按成员隔离，认不出说话人时记录进"待认领"区，只有户主能看到并认领。

**边界**：这不是医生。插件整理档案、提示该复查什么、什么情况必须就医，但不做诊断、不开药、不给剂量。

## 工具

| 工具 | 用途 |
|---|---|
| `health_report` | 整份体检报告：preview 看识别结果 → commit 落盘（含原文存档） |
| `health_measure` | 单个测量，一行一项：「名称 数值 单位 参考区间」；血压自动拆成两条 |
| `health_record` | 口头事实：症状、确诊、用药、过敏、疫苗、就诊、手术、家族史、生活习惯、基本资料 |
| `health_query` | 按时间/类型/指标查，或看未认领的记录 |
| `health_series` | 单个指标的历史与变化 |
| `health_review` | 红旗分诊 + 异常指标 + 该复查的项目 + 确定性建议 |
| `health_export` | 就诊摘要卡 / CSV |
| `health_claim` | 户主把未归属记录认领给某个成员 |
| `health_doctor` | 自检：条数、损坏行、认不出的项目、未归属记录 |

## 为什么值得单独做

体检报告的文本抽取出来后**表格结构已经没了**：一格一行，页眉页脚还会插进表格中间，中文常以部首形出现（`⻔`/`⻬`/`⻣`，NFKC 修不干净）。所以解析器不按列切，而是靠"中文名 + 缩写"这对锚点重建行；报告里的"提示"列抽出来是空的，异常全部由数值与参考区间自己比对得出。

## 现状

M0–M3 已完成：骨架、解析内核、测量与所见、报告导入、趋势、建议、导出。77 个测试，含一份真实体检报告的回归（21 页 → 65 行，无重复、无缺值）。

剩下的：M4 口头记录的追问链、M5 建议闭环（建议写成记录并与复查对上）、M6 语音/图片入口。

设计见 [DESIGN.md](./DESIGN.md)，词典种子见 [docs/analytes-seed.md](./docs/analytes-seed.md)。

```
npm run verify # 按 Cordis 的方式真的挂载一次插件
```

真实体检报告是个人数据，不进仓库：把脱敏后的文本放到 `test/fixtures/ikang-2026.txt`，测试会自动用它跑更严格的断言；没有这个文件时跑 `ikang-2026.example.txt`。
